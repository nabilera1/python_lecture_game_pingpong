2. 프로그램 코드 (핵심 부분)  
class AIPaddle(Paddle):                 # Paddle 을 상속한 컴퓨터 패들  
    def follow(self, ball):  
        if ball.rect.centery < self.rect.centery - 10:  
            self.rect.y -= self.speed  
        elif ball.rect.centery > self.rect.centery + 10:  
            self.rect.y += self.speed  
        self.rect.clamp_ip(SCREEN_RECT)     # 화면 밖으로 나가지 않게  
LEVELS = {"쉬움": {"ball": 4, "ai": 3},     # 난이도 설정 (딕셔너리 안의 딕셔너리)  
          "보통": {"ball": 6, "ai": 5},  
          "어려움": {"ball": 8, "ai": 7}}  
RULES = {("준비", "SPACE"): "진행", ("진행", "P"): "일시정지",   # 상태 전환표  
         ("일시정지", "P"): "진행", ("진행", "WIN"): "종료", ("종료", "R"): "준비"}  
records = []                                 # 경기 기록표 [[경기, 난이도, 나, AI, 결과], ...]

## Ⅶ. 교사 수업 설계 및 운영 유의사항

1. 수업 설계 측면  
• 게임은 학생에게 친숙하여 ‘문제 발견’의 진입 장벽을 낮춘다. 단, 게임을 ‘만드는 것’보다 ‘규칙을 분해·모델링하는 과정’이 목표임을 차시마다 강조한다.  
• 기본 버전(리스트·반복·조건) → 함수 버전 → 2차원 리스트·딕셔너리 → 클래스(핑퐁) 순서로 같은 문제를 더 좋은 구조로 다시 만드는 단계적 스캐폴딩을 제공한다. 제공 코드는 정답이 아니라 출발점이다.  
• 기본 버전 업다운 게임은 범위 밖 숫자(150)를 입력해도 기회가 줄어드는 등 의도적으로 개선 여지를 남겨 두었으므로 18차시 테스트 활동의 소재로 활용한다.  
• 수행평가 채점 기준(다차원 데이터 구조 25점)과 연결되도록, 19차시 계획서에서 2차원 리스트·딕셔너리 활용을 반드시 계획하게 한다.  
• 22차시가 부담되면 8차시 압축안(1→3→4→8→10→18→19·20→22)으로 운영하고, 12차시(BFS)는 심화 선택 차시로 운영할 수 있다.  
2. 수업 운영 측면  
• 모둠은 2~3명, 드라이버(코드 입력)·내비게이터(검토) 역할을 차시마다 교대한다. 수행평가는 개인 산출물 기준이므로 모둠 활동 후 개인별 코드를 완성·제출하게 한다.  
• 13차시 전에 실습실 PC에 pygame 설치 여부를 확인한다. 설치가 어려우면 14~16차시는 단계별 코드 읽기와 시뮬레이션형 코딩 테스트로 대체한다.  
• 기억력 게임의 화면 지우기(print("\n" * 40))는 IDLE에서 스크롤로 보일 수 있으며, 핑퐁의 한글 글꼴은 운영체제에 따라 다르므로 미리 확인한다.  
• 진도가 빠른 학생에게는 코딩 테스트 도전 문제·심화 과제를, 느린 학생에게는 활동지 빈칸형·의사코드를 먼저 제공한다. 교사 순회 시 정답 대신 “이 반복은 언제 끝나니?”와 같은 질문으로 피드백한다.  
3. 생성형 AI 활용 및 평가 유의사항  
• AI는 소스코드 작성·오류 수정 범위에서만 활용하며, 학번·이름·학교명 등 개인정보를 입력하지 않도록 매 차시 안내한다.  
• AI 활용 시 AI 활용 기록표를 작성하게 하고, 제출 코드에 대해 교사가 질의(“이 줄은 무슨 일을 하니?”)하여 설명하지 못하는 부분은 채점에서 제외될 수 있음을 사전에 안내한다.  
• 수행평가는 수업 시간 내에 진행하고, 수업 종료 후 활동지를 제출받는다. 과정 중심 평가로서 교사 관찰 기록을 함께 남긴다. 결시·학적변동 학생 처리는 학교 학업성적관리규정을 따른다.
